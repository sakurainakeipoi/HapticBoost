# v1.3.1 修复验证记录

日期：2026-10-24。设备：RMX3888，Android 16。

## 微信通知强度与普通预览不一致

旧预览固定使用 `oneshot -a 250 96`，实机记录为 `COMMUNICATION_REQUEST`、振幅 `0.38`。
设备中微信通知的记录为 `NOTIFICATION`，系统默认振幅解析为 `1.00`，常见节奏为
`[300, 200, 300, 200]`（停/震/停/震）；也存在其他通知节奏。

修复后使用 Android `Vibrator` 通知用途与默认振幅，不再把普通预览固定降到 96/255。
实机记录确认按钮预览的用途、强度缩放和播放波形与上述微信参考记录一致；
滑块松手使用同一用途、默认振幅及 200 毫秒短震。
这是参数与执行记录验证，实际手感仍需要用户与新收到的微信通知对比；不承诺所有应用和通知渠道的波形完全相同。

## 关联检查与修复

- 预览统一写入当前场景的三路电压，写后读取校验；播放结束后在 finally 中恢复并核对。
- 检测到来电增强令牌时不开始预览；预览期间出现来电令牌时按来电档恢复。
- 按钮与滑块预览共用忙碌状态，避免连续操作排队播放旧数值。
- `apply.sh` 对无效电压、写入失败和读回不符返回失败，避免末尾 echo 掩盖错误。
- 来电补偿命令明确指定振幅参数，并限制时长与间隔的最大值。
- 恢复原厂脚本先停止守护进程，再写原厂值，避免守护进程最后一次写入覆盖恢复结果。
- 配置解析接受合法缩进，拒绝跨行赋值；保存校验拒绝重复或冲突的节点读回。
- 保存前及应用日常档前检查来电增强令牌；状态卡要求三个节点均读取成功，避免部分节点失败仍显示成功。

## 微信来电增强中途退出

用户在振动模式下复现：17:51:13 进入来电档，17:51:14 因铃声模式读取失败退回日常档。
守护日志反复出现 `/system/bin/printf: Argument list too long`。Android 的外部 printf
无法接收过长的完整音频服务日志参数，因此模式解析得到空值，触发原有保守停震策略。
改为通过标准输入读取音频日志，同时修复铃声模式和通话接听状态两个解析入口。
没有放宽静音、未知模式或 dumpsys 失败时停止增强的条件。

实机使用同一份扩充至 256 KiB 以上的音频日志：旧解析返回 1，新解析返回 0，
正确读出 internal/external 均为 VIBRATE。补充大日志回归，覆盖振动、静音、
接听状态锁存与每次补偿震动前检查。手机模块已更新并重启守护进程；配置文件
更新前后 SHA-256 均为 `77b26975c87f289af2603ab90be71441e2e13845ee71bf67fc826ba75c099597`。
修复后用户确认真实微信来电增强生效；实机日志记录 17:56:09 进入来电档，
17:56:10 启动补偿震动，17:56:20 来电结束后停止并恢复日常档。
随后读取三路电压为 `1570/4780/1280`，与保存的日常设置一致，来电令牌和
补偿进程 PID 文件均已清除。此次实测未覆盖接听、静音切换及重启后的全部场景。

## 普通拨号来电被系统原生震动压制

17:59 实机记录确认：普通电话播放循环 `RINGTONE`，旧 shell 补偿请求为
`COMMUNICATION_REQUEST`，全部被系统以 `ignored_for_higher_importance` 拒绝。
因此只验证来电档切换、命令退出码或微信来电不足以确认普通电话增强。

增加 APK 内的 root `app_process` 入口 `RingtonePulse`，使用 `RINGTONE` 用途。
系统还会优先保留同优先级的循环震动，因此增强脉冲以循环效果提交，再由进程
按设置时长取消自身 Binder token；令牌撤销时每 25ms 检查并提前停止。
进程退出或异常时取消自身震动，单次最长 3000ms；不设置绕过免打扰的标志。
外层仍在每次播放前检查实时铃声模式。模块打包现在必须包含配套 APK。
同时将 Telecom 文本解析改为标准输入，兼容实机多空格缩进的响铃列表。

18:02:45 实机普通来电由 `ringList:1` 识别。原厂循环震动记录为
`cancelled_superseded`；18:02:47、51、55 的增强脉冲实际播放约 1500ms，
均为 `RINGTONE`、振幅 1.00。最后一个脉冲在 18:03:00 提前停止，日常
三路电压恢复为 `1570/4780/1280`，令牌和播放 PID 文件已清除。用户确认修复。
脉冲间隔包含模式检查和播放器进程启动开销，不是精确时钟节拍。

播放器通过 root 进程反射获取系统 Context；当前 RMX3888 实测通过，Lint 有一条
PrivateApi 兼容性警告，其他 Android 厂商或未来系统版本仍需实机验证。
